# cx-box 项目状态快照

**快照时间：2026-11-26 ｜ 当前版本：v0.5.19 ｜ 内核：sing-box 1.14.4**
每次发版后更新本文件。AI 接手先读 `AGENTS.md`，再读本文件。

## 1. 已完成（截至 v0.5.18，均为已发布状态）

- **主体**：面板 + 订阅双监听、登录（bcrypt）+ API token 鉴权、入站/出站/客户端/证书 CRUD、订阅下发、单文件前端（深色仪表盘状态页：版本、入站/客户端数、累计流量、公网/本机 IP、CPU/内存/磁盘/负载）。
- **协议**：入站与出站均支持 VLESS / VMess / Trojan / Shadowsocks（经典 + 2022）/ Hysteria2 / TUIC / AnyTLS，外加 SOCKS、HTTP（入站为网关式静态用户）；内置出站 direct / block / selector / urltest。每协议有默认模板与 Schema 驱动表单，默认端口：vless 443、vmess 8443、trojan 4443、ss 8388、hy2 36712、tuic 10443、anytls 9443、socks 1080、http 8080。
- **配置管线**：保存自动应用（失败 apply_error 明示）、临时文件校验后原子替换、生成期保护规则齐全（见 AGENTS.md 铁律）。
- **客户端治理**：流量配额 + 到期（生成时剔除）、流量按用户归因统计（内核 api service，仅回环 19090）、流量一键重置、IP 数限制（滑动窗口 + 防抖封锁）、可用入站多选、自定义订阅名、单节点导出（链接 + 二维码）。
- **出口体系**：selector 全局默认出口；出站分享链接批量导入（9 种 scheme）；按客户端指定出口（单选直达 / 多选自动合成 urltest 测速组）；订阅多出口派生节点（派生用户机制）。
- **证书**：一键自签、PEM 导入（配对校验、被引用禁删）、ACME 自动签发与续签（Cloudflare DNS-01，支持泛域名）、无证书时自动证书兜底、订阅侧 SNI 补全与自签 insecure 标记。
- **防火墙**：一键开关托管（ufw/firewalld/iptables），应用后自动同步端口；管理菜单 0–23（含 21 开启 / 22 关闭 / 23 查看状态）。
- **Clash 订阅**：订阅加 `?format=clash`（别名 mihomo）原生输出 Mihomo YAML（renderer 的 ClashProxy 映射，全协议含 ss 2022 组合密码、多出口派生节点；分组为自动选择 url-test + 节点选择 select + MATCH 规则）；未带 format 时按 UA 自动识别 Clash 系客户端返回 YAML，其余仍回 base64；面板导出弹窗带 Clash 地址与复制按钮。
- **发布**：GitHub Actions 按 `v*` tag 构建 5 个 Linux 架构包，install.sh 拉 Release 安装；全自动安装走 `CXBOX_AUTO=1`（随机账号与面板路径）。

## 2. 关键设计决策（为什么这样，以及不要改回去）

| 决策 | 原因 |
|---|---|
| 保存自动应用而非手动「应用配置」 | 发生过用户从未点应用、整机跑安装空配置导致全节点 -1 的事故 |
| Apply 先临时文件校验再原子替换 | 旧实现先覆盖后校验，坏配置留盘 + 服务重启 = 内核彻底起不来 |
| 按用户路由用 `auth_user` | sing-box 的实际语义；写 `user` 静默不命中，靠最小实验才定位 |
| 多出口用「派生用户」而不是多客户端 | 一个客户端要在订阅里同时有多个出口节点、又共用一份配额，只能靠确定性推导的派生凭据 + 路由直达 |
| 多选出口合成 urltest 组 | sing-box 原生能力：gstatic generate_204 探测、3 分钟间隔、选最低延迟 |
| 流量统计走内核 api service 而非 v2ray_api | 官方构建不带 with_v2ray_api，带上 experimental 配置 check 直接失败 |
| AnyTLS 密码三处统一 base64 | 协议矩阵的约定；已与 anytls-go / mihomo / sing-box 三方互通验证（详见 AGENTS.md 铁律 10） |
| ACME 接受 Ready 态 | x/crypto/acme 的 WaitOrder 语义；v0.5.15 误判导致首签必失败，v0.5.16 修复 |
| 防火墙先放行后启用、同步失败不阻断应用 | 防管理员把自己锁在门外；防火墙是增强项，不能拖垮主流程 |
| 前端单文件、无构建 | 升级只换一个二进制是本项目的核心卖点，不要引入 Node 构建链 |

## 3. 已知限制（未实现，不要当成已支持来宣传）

- 通用路由规则的可视化编辑 UI（RoutingRule 模型已在库中，界面未做）；
- 面板自身 HTTPS（现靠随机路径 + HTTP，需加密请自行套反代）；
- 入站级指定出站（出口指定目前是客户端级）；
- API token 的列表 / 删除界面（仅 CLI 生成；删除走数据库）；
- direct 出站的 inet4_bind_address / bind_interface 透传（本机第二 IP 做出口）。

## 4. 待所有者决策（未批准，不要动手）

- 普通 TLS 入站保存时校验 SNI 是否在所绑证书域名内、不符则提示（Reality 除外）。背景：真实事故——AnyTLS 入站绑真证书但 SNI 填了 www.apple.com、无 insecure 豁免，客户端校验必挂（有延迟、打不开），定位耗时很久。
- 管理菜单在检测不到防火墙后端时提供一键安装 ufw（目前是提示用户手动 apt 安装）。

## 5. 所有者已否决 / 搁置（不要主动做、不要反复问）

- 本机第二 IP 做出口（direct bind 透传）：2026-11-15 明确「先不做」。
- 入站指定出站：2026-11-17 明确本版不做、搁置。
- API token 管理 CLI（列表/删除）：明确先不加。

## 6. 生产使用概况（仅形态，具体地址与凭据不在仓库内）

- 所有者自用部署，典型拓扑为「中转机（cx-box 入站）→ 落地机（住宅 IP 出口）」，客户端多选出口 + 派生节点是主力用法；
- 部署侧细节（服务器地址、面板路径、账号、令牌）由所有者单独保管，**禁止写入本仓库任何文件**。
