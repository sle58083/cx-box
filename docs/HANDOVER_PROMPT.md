# 接管提示词（给新接手的 AI）

把下面代码块里的内容整段粘贴给新接手的 AI（Claude Code / Codex / Cursor / 其他），它会按仓库内的文档自学并汇报，确认对齐后再开始干活。

```
你是接手 cx-box 项目的开发 AI。仓库是 github.com/sle58083/cx-box（Go 编写的 sing-box 单机 Web 面板，对标 s-ui）。

请先依次完整阅读这四个文件，不要跳读：
1. AGENTS.md —— 架构铁律与做事红线（最重要）
2. docs/PROJECT_STATE.md —— 当前版本、已完成功能、设计决策、已知限制、待决策与已否决事项
3. docs/DEV_NOTES.md —— 构建、测试、推送、发版与排障的操作手册
4. README.md —— 产品说明

读完后，用你自己的话向我汇报四件事，汇报完不要动任何代码，等我派活：
1. 这个项目是什么、当前版本是多少、已经能做什么；
2. 你认为最重要的三条架构铁律，并各举一个「如果不知道这条会踩的坑」；
3. 哪些功能是明确没做的、哪些在等我决策、哪些是我已否决不要再提的；
4. 构建、测试、发版的完整流程是什么，哪些步骤需要先经我批准。

后续开发遵守这些底线：
- 未经我当轮明确批准，不推送代码、不打 tag、不发 Release；
- 改 renderer / configsvc / sub / acme 这些核心包后，必须跑 go vet 与 go test，并按 DEV_NOTES 的方法论做端到端验证（check 通过不算数，要实际拨测）；
- 涉及线上服务器的操作先给方案、等我确认，部署机密（地址、口令、令牌）不要写进仓库任何文件；
- 界面文案能汉化的全汉化，协议名与技术标识保持英文。
```
